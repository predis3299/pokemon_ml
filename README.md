포켓몬은 생긴 대로 강할까?
==========================

**키·몸무게·색상·몸 형태를 이용해서 종족값 총합을 예측하는 입문용 머신러닝 프로젝트입니다.**

종족값 총합(BST)은 HP + 공격 + 방어 + 특수공격 + 특수방어 + 스피드입니다.
게임의 실제 승률이 아니라 이 기본 능력치의 합을 예측합니다.

**이 파일들만 보면 됩니다.**

| 파일 | 하는 일 |
|---|---|
| `01_collect.py` | PokéAPI에서 데이터를 가져와 CSV로 저장 |
| `02_train.py` | 데이터를 나누고 모델을 학습한 뒤 결과 비교 |
| `data/pokemon.csv` | 포켓몬 1,025종의 데이터 |
| `results.csv` | 실행 후 생성되는 모델별 평균 오차 |
| `result.png` | 실행 후 생성되는 비교 그래프 |

**실행 방법**

현재 준비된 환경에서는 VS Code 터미널(PowerShell)에 다음 명령을 입력합니다.

```powershell
cd C:\Workspace\TES\pokemon_ml
.\.venv\Scripts\python.exe 01_collect.py
.\.venv\Scripts\python.exe 02_train.py
```

데이터는 이미 PokéAPI에서 수집해 두었습니다. 첫 번째 명령은 저장된 CSV를 확인하고,
두 번째 명령은 학습과 평가를 실행합니다. 데이터가 없을 때만 API에서 새로 수집합니다.

새 PC에서는 Python을 설치한 뒤 `python -m pip install -r requirements.txt`로
필요한 라이브러리를 설치하고 `python 01_collect.py`, `python 02_train.py`를 실행합니다.

**코드를 읽는 순서**

1. CSV를 읽고 결측값·중복 행을 확인합니다. 문제가 있으면 학습을 멈추고 데이터를 확인합니다.
2. 데이터의 80%는 학습용, 20%는 평가용으로 나눕니다.
3. 외형을 보지 않고 학습 데이터의 평균 BST만 답하는 기준선을 만듭니다.
4. 랜덤 포레스트에 키·몸무게를 넣어 학습합니다.
5. 같은 모델에 색상·몸 형태까지 넣고 평균 오차를 비교합니다.

랜덤 포레스트는 여러 결정나무의 예측을 평균 내는 모델입니다.
색상·몸 형태처럼 글자로 된 입력은 `pd.get_dummies`로 0과 1의 열로 바꿉니다.
이때 포켓몬 이름과 정답 BST는 입력에 넣지 않습니다.

**결과를 읽는 방법**

- `Mean baseline`: 외형 없이 평균값만 예측
- `Height + weight`: 키·몸무게로 예측
- `All appearance`: 키·몸무게·색상·몸 형태로 예측
- `MAE`: 실제 BST와 예측 BST의 평균 차이. 예를 들어 60이면 평균적으로 60점 틀렸다는 뜻입니다.

외형 모델의 MAE가 기준선보다 낮으면 외형 정보가 예측에 도움이 된 것입니다.
전체 외형 모델이 키·몸무게 모델보다 나은지 보면 색상·몸 형태의 추가 효과도 비교할 수 있습니다.

**이번 간단한 코드의 실행 결과**

| 모델 | 평균 오차(MAE) |
|---|---:|
| 평균값만 예측 | 97.60 |
| 키·몸무게 | 59.62 |
| 키·몸무게·색상·몸 형태 | 58.84 |

외형을 사용하니 평균값만 답할 때보다 오차가 줄었습니다.
색상·몸 형태를 추가한 차이는 작았습니다. 한 번의 평가 결과이므로 일반화해서 단정하지 않습니다.

**알아둘 점**

한 번 나눈 데이터에서 얻은 입문용 실험 결과입니다. 같은 진화 계열이 학습·평가 양쪽에 들어갈 수 있습니다.
성능을 높이려고 평가 결과를 보며 설정을 계속 바꾸지 않습니다.
외형과 능력치의 관련성을 확인하는 실험이며 인과관계를 증명하지는 않습니다.

데이터 출처: [PokéAPI](https://pokeapi.co/docs/v2).
기존의 복잡한 코드·노트북·실험 결과는 `_archive/advanced_v1/`에 보관했습니다. `_archive/`는 `.gitignore`에 추가해 Git 업로드에서 제외합니다. 수동으로 제출할 때도 이 폴더는 빼면 됩니다.
기존 보고서는 이전 실험 결과이며 이번 간단한 코드의 결과는 `results.csv`를 확인합니다.

**다른 주제 아이디어**

현재는 외형으로 BST를 예측하는 프로젝트를 진행합니다. 아래는 추후 선택할 수 있는 아이디어이며 아직 구현하지 않았습니다.

| 주제 | 입력 → 예측 또는 결과 | 간단한 방법 |
|---|---|---|
| 기술 이름으로 물리·특수 공격 구분 | 기술 이름 → 물리 / 특수 | TF-IDF + 로지스틱 회귀. 변화 기술은 우선 제외 |
| 강한 포켓몬은 잡기도 어려울까? | 능력치·타입 → 기본 포획률 수치 | 랜덤 포레스트 회귀. 실제 포획 성공 확률(%)과는 구분 |
| 기술이 강하면 대가가 있을까? | 명중률·PP·타입·공격 분류 → 기본 위력 | 랜덤 포레스트 회귀. 고정된 위력이 있는 공격 기술부터 사용 |
| 포켓몬의 전투 성향 묶기 | 능력치 배분 비율 → 비슷한 포켓몬 그룹 | K-means 군집화. 그룹을 만든 뒤 특징에 맞게 이름 붙이기 |
